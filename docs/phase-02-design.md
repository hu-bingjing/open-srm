# Phase 02 实现基线

本阶段：公司、工厂、跨公司采购组织、供应商及公司关系、组织授权、供应商用户绑定和数据隔离。保留 Phase 01 身份功能，追加 Flyway V3，不改写 V1/V2；先在独立测试库验收，部署前在原测试机备份数据/私有配置并保留旧镜像。

## 权限粒度

- ADMIN 是部署级身份/组织目录/授权管理员；允许创建第一个公司和维护目录，不隐含供应商业务范围。供应商读取/管理仍需显式公司范围。
- BUYER 具有组织读取、供应商读取/维护动作；SUPPLIER 只具有组织/自身供应商读取动作。角色与组织授权同时满足才生效。
- SUPPLIER 与其他角色互斥，且只能绑定一个供应商。未绑定账号没有供应商数据；绑定/角色变化撤销旧会话。已绑定账号转内部角色之前必须显式解除绑定。
- 授权为完整的 permission/company/plant?/purchasingOrg? 元组。工厂必须属于该公司，采购组织必须关联该公司，不拼接不同元组。
- 目录按元组可见范围显示，公司名只是目录锚点；工厂和采购组织可按另一维度进一步过滤。限定工厂/采购组织的授权不扩大为公司级供应商档案或审计权限。
- 供应商档案及其公司关系是公司级数据，读取/维护需要对应的公司级授权（plant/purchasingOrg 均不限）。supplier.manage 包含该范围的 supplier.read；有效的数据授权同时允许查看其组织目录。
- 供应商用户还需满足绑定供应商相同、公司关系有效、公司有效。冻结供应商可读历史；公司关系撤销后供应商用户立即不可读该关系。内部用户在授权公司可维护已停用的供应商公司关系。
- 共享供应商名称/全局状态修改影响多公司，必须覆盖全部关联公司的有效管理范围；未完整授权时不返回其他公司的名称/编号，只拒绝全局修改。单公司关系修改仅影响该公司。
- 公司/工厂/采购组织停用不删除数据；工厂公司归属与所有业务编码在创建后不可改。采购组织移除公司采用停用关系，保留引用。

## 一致性与审计

写入继续使用现有实例行锁，权限检查、版本、幂等结果和审计同事务。提取共享命令执行器供身份/组织/供应商复用，不建立第二套幂等实现。
重放之前重新检查当前动作、对象范围及原响应中的公司可见性，撤销权限不能取回缓存中的越权响应。If-Match 在首次执行时检查，合法重放返回原结果。
列表与 total 均在 SQL 内过滤后分页，详情/写入也检查范围；采购组织与供应商响应仅列出当前可见公司关系。
组织/供应商审计记录不可变公司范围；AUDITOR 的身份审计延续 Phase 01，业务审计另需公司级 audit.read 授权，不能凭角色读取其他公司事件。

## 验收门槛

真实 PostgreSQL HTTP 验收覆盖：V1/V2 升级；多公司/多工厂/跨公司采购组织；部分范围目录过滤；供应商多公司服务；越公司/越供应商列表、详情、筛选和计数；批量混入越权公司整批回滚；角色无范围及范围无角色；撤销/停用/重新绑定后的访问；重复提交、冲突版本、并发及审计隔离。
页面必须通过真实 API 持久化，不使用静态演示页面。原测试实例只追加独立命名的虚构验收数据和专用验收账号，不修改既有管理员资料/口令，不执行清卷或原库重置。
所有凭据、数据库备份、截图留在测试机私有/临时目录，不导出至公开源码。完整 SaaS、采购订单、ERP 同步及生产验收不在本阶段。
