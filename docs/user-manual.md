# OpenSRM 操作手册

适用版本：0.8.0｜更新日期：2026-11-10｜适用对象：系统管理员、采购员、供应商和审计人员。

本手册按当前实际页面编写。当前 SAP 测试系统没有业务数据，ERP 写入关闭。订单和实际收货来自来源系统；系统不会因创建 ASN 自动增加收货数量。

## 1. 使用前先了解

### 1.1 业务流程

建立组织与供应商 → 创建账号并授权 → 配置只读来源映射 → 同步采购订单 → 供应商确认 → 采购审批延期 → 形成交货计划 → 供应商提交 ASN → 同步 ERP 收货/冲销 → 查看账本、通知和统计。

| 概念 | 含义 |
| --- | --- |
| 采购订单 | ERP 导入的订单头、行项目及计划行，保留来源版本 |
| 供应商确认 | 供应商对某计划行的数量和交期作出的承诺，可分次确认 |
| 交期申请 | 晚于要求日期的确认或已有承诺的改期，需要独立采购审批 |
| 交货计划 | 生效确认对应的计划，不代表已经发货或已经收货 |
| ASN | 送货通知；草稿不占量，提交后预留可发数量 |
| 实际收货 | 由 ERP 收货凭证导入的数量，与 ASN 独立记账 |
| 收货冲销 | 引用原收货的反向事件，保留原凭证和冲销历史 |
| 一致性冻结 | 来源版本或数量需要核对时阻止新增协同，历史仍保留 |

### 1.2 当前环境边界

当前版本可进行本地组织、授权及协同操作。SAP 为空壳时，采购订单、收货和统计显示空数据是正常现象。真实 SAP 数量对账须等非生产来源有业务数据后补验。Mock 是演示来源，选择其场景会生成新的虚构业务数据；准备空白使用环境时不要运行演示或自动化 E2E。

ERP 写入保持关闭。页面中的提交确认、审批和 ASN 只写入 SRM，不向 SAP 创建采购单、收货、财务凭证或 ASN。

## 2. 登录与首次初始化

### 2.1 登录

1. 使用浏览器打开部署人员提供的 HTTPS 地址。
2. 输入“账号”和“密码”，点击“登录工作空间”。
3. 登录后在“我的工作空间”查看账号、显示名称和角色。
4. 可修改“个人显示名称”，点击“保存资料”。
5. 离开共用电脑前点击“退出登录”。

系统没有固定默认账号或密码。证书信任问题由部署人员处理；不要将忽略证书校验作为日常使用方式。角色或供应商绑定变更后，旧会话会失效，需要重新登录。

### 2.2 首次初始化，仅未初始化实例

1. 页面显示“初始化工作空间”时，向部署人员取得本实例的初始化令牌。
2. 填写“初始化令牌”“管理员账号”“显示名称”“管理员密码”。
3. 管理员账号至少 3 位，使用小写字母、数字或点、下划线、短横线；首字符为小写字母或数字。
4. 密码至少 12 个字符，UTF-8 编码最多 72 字节。中文等字符可能占多个字节。
5. 完成初始化后，使用新管理员账号登录。初始化入口随即关闭。

已有管理员时，不需要重新初始化。清理测试数据若选择保留初始管理员，继续使用该账号；若明确选择清空全部账号，则由维护人员完成重置后再执行本节。

### 2.3 当前账号管理能力

当前页面支持新建用户、角色调整、启用/禁用及显示名称维护；没有自助找回密码、修改/重置密码或单点登录入口。忘记密码时联系维护人员处理，不要自行修改数据库密码哈希。

## 3. 角色、菜单与数据范围

角色决定能够做什么；组织授权和供应商绑定决定可以处理哪些数据。管理员也不自动拥有所有公司的业务数据。

| 身份 | 常用入口 | 还需配置 |
| --- | --- | --- |
| 系统管理员 ADMIN | 用户与角色、公司管理、工厂管理、采购组织、供应商管理、ERP 同步监控 | 供应商、同步、订单等公司范围按需授权 |
| 采购员 BUYER | 采购订单、订单协同、统计分析、供应商管理 | 订单查看；承担审批时另授采购交期审批范围 |
| 供应商 SUPPLIER | 采购订单、订单协同、送货与实际收货 | 单一供应商绑定、订单查看、确认提交、ASN 管理范围 |
| 审计员 AUDITOR | 操作审计及授权业务数据 | 业务审计须授对应公司范围；身份审计与业务审计范围不同 |
| 普通用户 USER | 我的工作空间、本人通知 | 仅有账号并不等于有采购业务能力 |

菜单按角色动作显示；列表按当前有效数据范围过滤。看不到按钮、列表为空和没有收到某通知，均可能与权限或业务状态有关，不应通过更换 URL 绕过。

## 4. 管理员：建立基础资料

建议先建公司，再建工厂和采购组织，最后建供应商、账号及授权。

### 4.1 公司

1. 打开“公司管理”，点击“新建公司”。
2. 填写业务编码、业务名称和时区，例如 Asia/Shanghai。
3. 确认“有效”后点击“保存”。
4. 后续通过“编辑”修改名称、时区或有效状态。

公司时区用于业务日期判断，包括工作台逾期判断。编码按稳定业务键规划，创建后页面不支持修改编码。

### 4.2 工厂和采购组织

1. “工厂管理”→“新建工厂”，填写编码、名称并选择所属公司。
2. “采购组织”→“新建采购组织”，填写编码、名称并选择一个或多个关联公司。
3. 保存后用查询条件检查关联是否正确。

工厂所属公司创建后不可直接改动。停用公司、工厂或采购组织会立即影响相应范围的业务访问。

### 4.3 供应商

1. “供应商管理”→“新建供应商”，填写编码、名称和关联公司。
2. 维护既有供应商时，可编辑名称或将状态设为冻结。
3. 点击“公司关系”，选择公司和“关系有效”，点击“保存公司关系”。

共享供应商的名称及状态修改要求覆盖其全部关联公司的管理范围。停用公司关系保留历史；相应供应商账号将失去该公司数据访问权限。冻结供应商会阻止新的供应商业务写入。

## 5. 管理员：账号与授权

### 5.1 创建账号和调整角色

1. 打开“用户与角色”，点击“新建用户”。
2. 填写登录账号、显示名称、初始密码，选择角色，点击“创建用户”。
3. 供应商账号仅选择“供应商用户”；供应商角色不能与其他角色混选。
4. 在账号列表点击“角色”可调整角色；保存后该账号旧会话失效。
5. 离职或停用时点击“禁用”；需要恢复时点击“启用”。

不能禁用当前登录的自己，也不能移除最后一个有效管理员。普通页面只提供禁用，没有永久删除账号或批量清除数据功能。

### 5.2 配置组织范围

1. 在目标账号行点击“数据授权”，打开“组织与供应商授权”。
2. 选择权限、授权公司；按需限制工厂和采购组织。
3. 点击“添加授权”，检查下方范围列表。
4. 需要收回权限时点击该条授权的“撤销”。

一条授权中的公司、工厂、采购组织共同组成范围。工厂和采购组织留空表示该公司内相应维度全部，而不是没有权限。不同授权记录不能拼接成越界范围。

| 使用目标 | 建议角色及业务范围 |
| --- | --- |
| 查看订单、交货计划、收货与统计 | ADMIN、BUYER、AUDITOR 或 SUPPLIER 的相应动作，加“采购订单查看”范围 |
| 供应商确认与改期 | SUPPLIER，加“采购订单查看”“供应商确认提交”，并完成供应商绑定 |
| 供应商 ASN | SUPPLIER，加“采购订单查看”“ASN 送货管理”，并完成供应商绑定 |
| 采购交期审批 | BUYER，加“采购订单查看”“采购交期审批” |
| 管理来源和同步 | ADMIN，加公司级“供应商管理”“公司同步管理”；连接归属也会校验 |
| 供应商资料维护 | 具备供应商管理动作的身份，加公司级“供应商管理” |

### 5.3 绑定供应商

1. 目标账号角色为 SUPPLIER 时，授权抽屉显示“供应商账号绑定”。
2. 选择一家供应商，点击“保存绑定”。
3. 同时确认供应商与公司关系有效、该账号的业务授权范围正确。
4. 绑定变化后让该用户重新登录。

一个供应商账号只绑定一家供应商。仅绑定或仅授公司范围，均不足以访问供应商业务。

## 6. 管理员：来源映射与只读同步

### 6.1 建立来源连接

1. 给操作账号授予目标公司级“供应商管理”“公司同步管理”，再重新进入页面。
2. 打开“ERP 同步监控”，点击“新建连接”。
3. 选择适配器、已有公司、采购组织、供应商及工厂，填写连接名称。
4. SAP 连接还需来源系统标识、SAP Client、外部公司/采购组织/供应商键及外部工厂映射。
5. 保存后在“同步连接”选择该连接。

实际按钮和表单以当前页面为准。SAP 地址、CA、用户名、密码及精确订单白名单由维护人员在私有配置管理，不在网页录入。普通管理员不能查看其他连接负责人的任务和异常。

### 6.2 执行和查看同步

1. 选择“同步连接”和“同步任务类型”，点击“启动同步”。
2. 查看任务状态、处理、更新、跳过、隔离、重试及安全错误码。
3. 点击“检查点与异常”查看失败位置和隔离原因。
4. 任务失败且允许重试时，点击“重试”；系统沿用原检查点，不从头重复生成业务。

同一连接已有排队/运行任务时，不要重复启动。持续失败应先定位配置、范围或来源数据问题，再重试；不要用反复点击替代排查。

### 6.3 SAP 空壳系统如何使用

可执行“验证接口元数据”，用于核实只读服务契约。当前 SAP 没有订单或物料凭证，所以不能演示真实订单、收货和冲销。未配置精确业务范围时，“读取授权采购订单”或“读取授权收货及冲销”会失败关闭，可能显示 SAP_SCOPE_NOT_CONFIGURED。这不是要求用户编造单据。

将来有获准的非生产数据后，由维护人员按样本配置白名单和映射，再进行真实对账。ERP 写入开关继续关闭。

### 6.4 Mock 演示，按需使用

Mock 提供初始订单、部分确认、来源改版、收货和冲销等固定场景。只有明确需要演示时才在独立演示组织/账号下运行；它会重新产生测试数据。不要把 Mock 收货当成 SAP 凭证或实际业务验收。

## 7. 采购订单查看与供应商确认

### 7.1 查询订单与版本

1. 打开“采购订单”，输入采购订单号并按需选择公司、工厂，点击“查询订单”。
2. 在订单行点击“订单与版本”。
3. 核对来源版本、供应商、物料、单位、订购数量、要求交期和未确认余额。
4. 在“不可变来源版本”查看历史来源，历史记录不会被当前版本覆盖。

订单由来源系统同步，当前页面不提供手工新建采购订单。“待一致性核对”订单会冻结新增协同；不要重复提交以绕过冻结。

### 7.2 部分确认

1. 供应商账号在有效、未冻结订单的计划行点击“部分确认”。
2. 填写“本次确认数量”和“确认交期”。
3. 交期晚于要求日期时填写“延期原因”。
4. 点击“提交订单确认”，再到“订单协同”检查结果。

例如计划数量为 100，先按期确认 60，再对余下 40 提出延期。该例仅说明规则，不会自动创建数据。按期确认直接生效；延期部分预占余额并等待审批。数量必须为精确正十进制，累计生效量与待批预占不得超过计划数量。

## 8. 交期审批、改期及交货计划

### 8.1 采购审批

1. 采购员打开“订单协同”→“交期申请与审批”。
2. 找到“待审批”申请，核对原日期、申请日期、来源版本及原因。
3. 点击“审批”，选择“批准”或“拒绝”，填写审批意见，点击“提交审批决定”。
4. 点击“审批记录”查看决定和处理时间。

申请人不能审批自己提交的申请。批准首次延期后生成等量交货计划；拒绝或申请人撤回后释放相应待批预占。

### 8.2 已生效承诺改期

1. 供应商在“订单协同”→“供应商确认”找到生效记录。
2. 点击“申请改期”，填写申请交期和改期原因。
3. 提交后由采购员独立审批。原承诺在批准前继续有效。
4. 批准后以新日期替换等量计划；拒绝或撤回时原计划不变。

申请人可在“交期申请与审批”撤回自己的待批申请。来源改版、关闭、取消或版本冲突时，应先刷新并核对，不使用过期页面提交。

### 8.3 查看交货计划

打开“订单协同”→“交货计划”，核对订单、行项目、计划行、工厂、来源版本、数量及交期。交货计划来自生效确认，不支持直接把数量改大，也不等同于已发货或已收货。

## 9. 供应商：ASN 与分批送货

### 9.1 新建或编辑草稿

1. 打开“送货与实际收货”→“ASN 送货通知”，点击“新建 ASN 草稿”。
2. 填写唯一“送货通知号”，使用字母、数字、下划线或短横线。
3. 在“添加交货计划”中选择计划，点击“添加计划行”。可翻页选择其他计划。
4. 为各行填写“本批送货数量”，移除不需要的行。
5. 点击“保存 ASN 草稿”。草稿保存不会预留数量。

已有草稿可点击“编辑草稿”继续修改；通知号创建后不能直接修改。订单版本变化时，移除并重新添加计划行，重新确认来源版本与可发数量。

### 9.2 提交和取消

1. 检查草稿各行后点击“提交送货”。
2. 提交成功后状态为“已提交（未代表收货）”，对应数量计入有效 ASN，并预留可发余额。
3. 同一计划允许分批送货，但累计数量不能超出有效计划和来源约束。
4. 需要取消时点击“取消 ASN”。有过收货分配的 ASN 当前不允许直接取消，即使后来已全额冲销。

点击“数量账本”查看累计有效 ASN、ERP 净收货、在途及可发余额。提交 ASN 后 ERP 净收货保持不变，直到来源实际收货事件导入。

## 10. 实际收货、冲销及数量核对

1. 有同步权限的负责人在“ERP 同步监控”选择对应只读收货任务并执行。
2. 业务用户进入“送货与实际收货”→“ERP 实际收货与冲销”，点击“刷新实际收货”。
3. 核对 ERP 凭证复合键、订单行、计划行、事件类型、来源数量、过账日期和收货状态。
4. 点击“凭证与分配”查看关联 ASN、分配数量及冲销对应原收货。
5. 与“数量账本”和“统计分析”交叉核对，按相同公司、工厂、单位及历史口径比较。

| 数量口径 | 说明 |
| --- | --- |
| ERP 净收货 | 来源收货减去来源冲销，不因 ASN 提交而增加 |
| ASN 在途 | 每条有效 ASN 的送货量，扣除分配到该 ASN 行的净收货 |
| 未分配收货 | 仍计入 ERP 净收货，不自动冲减其他 ASN 的在途 |
| 不同单位 | 分开显示，不能直接把件、公斤等相加 |

当前 SAP 适配范围为 101 收货及 102 引用冲销；不能将其理解为已覆盖全部库存移动类型。多计划行无法确定映射、来源异常或超收时，交维护人员核查隔离记录，禁止在 SRM 人工补写收货数量。

## 11. 工作台、通知、统计和审计

### 11.1 协同工作台

点击“协同工作台”，可查看当前可见订单、待确认计划行、待我审批、逾期未发完计划、一致性冻结、本人失败同步及未读通知。点击卡片或“进入处理”前往对应模块，再按模块筛选定位事项。

“我的待办”每类最多显示 10 项，并非完整业务清单。逾期按公司时区判断；刷新后重新依据当前权限、来源版本和业务状态计算。

### 11.2 通知中心

1. 打开“通知中心”→“我的通知”。
2. 可勾选“只看未读”，点击“刷新通知”。
3. 点击“查看订单”或“查看同步”进入相应模块；通知入口不会绕过实时权限。
4. 点击“标为已读”，刷新后状态仍保留。

通知仅对本人且当前仍可见的事件提供访问。通知是提示，办理业务时以当前订单和状态为准。管理员“投递监控”只显示其有业务范围权限的事件；失败可按页面允许条件“重试投递”，历史通知不会因重试重复生成。

### 11.3 统计分析

打开“统计分析”，按“统计公司”“统计工厂”筛选并点击“刷新统计”。每行按公司、工厂和单位分别列出当前订购量、生效确认量、待批确认量、有效 ASN 量、ERP 净收货及 ASN 在途。

订购和确认采用当前来源版本；ASN、收货和在途包含保留的历史版本。来源改版后不能直接把这些列当作同一个版本的简单差额。

### 11.4 操作审计

具备审计角色/范围的账号可打开“操作审计”，查看时间、操作、操作人 ID 和追踪编号。需要排查问题时提供操作时间、入口、错误码及追踪编号；不要把密码、初始化令牌或完整私有配置发到聊天或工单。

## 12. 常见问题与处理

| 现象 | 建议处理 |
| --- | --- |
| 登录后没有业务菜单 | 先核对角色；有角色但列表为空，再核对公司/工厂/采购组织范围及供应商绑定 |
| 采购订单或收货为空 | 核对是否已有来源数据；当前空壳 SAP 本来没有业务单据 |
| 修改角色后退出登录 | 正常安全机制，使用新角色重新登录 |
| 供应商无法操作 | 检查绑定、供应商状态、公司关系、授权、来源版本及订单是否冻结 |
| 提示版本冲突或 SOURCE_REVISION_CONFLICT | 关闭编辑窗口，刷新最新对象后重新核对；不要在旧版本反复提交 |
| 提示 QUANTITY_EXCEEDED | 核对生效、待批预占、已提交 ASN 和剩余可发数量 |
| 提示 SAP_SCOPE_NOT_CONFIGURED | 业务白名单/组织范围未就绪；当前空壳环境不需要反复启动业务任务 |
| 提示 SAP_MAPPING_NOT_APPROVED | 维护人员核对私有映射及应用连接范围，不能在页面扩大范围绕过 |
| 提示 401 | 登录已失效，重新登录 |
| 提示 403 | 缺少动作能力或请求安全校验未通过；正常页面重登后仍失败则联系维护 |
| 提示 404 | 对象不存在或当前账号无数据范围，先核对授权 |
| 同步持续失败 | 查看安全错误码和“检查点与异常”，修正原因后按允许次数重试 |
| 订单待一致性核对 | 保留历史并暂停新增协同；当前没有通用人工/自动解除冻结入口 |
| ASN 已提交但收货仍为零 | 正常：需来源系统有实际收货凭证并同步后才改变净收货 |

## 13. 管理员维护：清理测试数据

这是部署维护操作，不是普通网页按钮。仅在明确授权的测试实例执行，并先确定是否保留初始管理员；不能把日常业务停用当作物理删除。

1. 盘点账号、测试组织和全部业务表，识别非测试数据和需保留的管理员。
2. 确认 ERP 写入为 false，停止新的业务操作，等待同步/通知任务稳定。
3. 保留清理前数据库备份、配置和核对清单，记录恢复位置；原备份及数据卷不删除。
4. 在停机维护窗口中，以事务清除已确认的测试业务、测试主数据、测试授权/账号及其会话、通知、幂等和测试审计。
5. 保留数据库结构、迁移历史、系统角色/动作、部署标识、TLS 和 SAP 私有配置；保留管理员时，其账号/密码和角色不变。
6. 将过期的 E2E 测试凭据/状态文件归档，避免后续维护脚本继续使用已删除测试账号。
7. 重启并核对服务健康、保留账号登录、空白数据状态和旧测试账号不能登录。全部账号清空模式还需核对首次初始化入口。
8. 写入清理时间、执行范围和结果记录。此后历史验收基线作为清理前证据保留，不再用它判断“原测试记录必须仍存在”。

清理后，普通管理工作从建立正式组织与授权开始；运行 Mock 演示或全套 E2E 会再次生成测试数据。当前手册本身不执行清理，不包含可误用于其他环境的一键清库命令。
