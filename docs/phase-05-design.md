# Phase 05：ASN 与 ERP 实际收货

状态：已完成业务实现及测试部署验收，实际证据见阶段记录。V6 仅追加迁移，不修改 V1–V5。

## 数量口径

ASN 是供应商发货声明，提交只增加预留在途量，不增加实际收货。实际收货只能由 GoodsReceiptProvider 导入。页面分别展示订购、有效确认、累计发货、ERP 净收货、在途和可发量。

同一逻辑订单行/计划行的跨版本账本必须连续，不能因新来源版本创建了新 schedule UUID 而丢失历史占用。逻辑键由连接、订单外部键、行号、计划行号组成，单位变化进入异常。

Q 为当前订购数量，C 为当前有效确认数量，R 为 ERP 收货减冲销的净量，T 为提交 ASN 数量减已分配净收货的在途量。可发量为 max(0,min(C,Q)-R-T)。另按每个交货计划校验累计提交数量不超计划量；收货和冲销均不恢复该计划已经使用的发货额度。冲销被分配的收货会恢复对应在途占用；不自动取消 ASN。

无 ASN 收货增加 R，不扣减任何 ASN 的 T。超收事件保留真实来源数量，不截断；冻结新增协同并显示差异。订单取消、移除行、缩量或改单位也必须检查历史收货与在途。

## ASN 命令

头和多行必须同供应商、公司，允许不同已授权工厂及订单。DRAFT 不占量，SUBMITTED 占量；一份计划可以多批 ASN，一份 ASN 可以多行。重复计划行输入拒绝，避免单次命令内累计漏算。

草稿创建、修改、提交和取消使用独立动作 asn.manage、供应商绑定及完整组织元组；读取同时要求 order.read。头级列表、计数和详情仅在全部行均授权时返回，避免泄露未授权行。提交时验证 ASN If-Match、每个订单当前来源及本地版本、计划/确认有效状态、供应商未冻结、订单无一致性冻结。事务复用 app_guard 锁，所有行一起校验、写入、审计和幂等入账。

未发布到 ERP 的本地 SUBMITTED 可在没有任何收货分配、发布未开始时取消，释放在途；ACKNOWLEDGED 或 UNKNOWN 禁止本地取消。本阶段真实 ERP 发布关闭，不能把本地提交伪装成 ERP 已受理。幂等重放前重新验证权限、绑定、冻结和来源版本。

## ERP 收货与冲销

扩展 GoodsReceiptProvider 事件为来源复合键、来源摘要、逻辑行键、类型 POSTED/REVERSAL、正数量、过账日及可选原收货引用、可选 ASN 分配。外部键至少包括连接、来源系统/客户端、凭证年度、凭证号、凭证行，不能只按凭证号去重。

原始收件箱不可变；唯一来源键同摘要重复忽略，异摘要隔离。凭证事件不可变，冲销追加新事件，并验证原事件存在且累计冲销量不超原量。冲销先到、映射未知、单位错误或分配错误保留原始事件和异常，允许修正映射后受控重试，不能假造收货或扣成负数。

一条收货可分配多个 ASN 行：每项数量为正、同逻辑计划行、合计不超收货量、不超对应 ASN 剩余在途。支持剩余未分配收货，仍计 R；部分冲销需携带明确分配，不能猜测冲销哪个 ASN。

同步经 sync.manage 的公司完整范围授权，持久保存任务、分页游标、已处理数、重复数和异常数；导入事件、分配、订单冻结、检查点、审计同事务。通过 Mock 适配器提供可重复场景，不提供接受任意人工收货数量的业务接口。

## 版本联动

Phase 04 的 supersede 在引入 ASN 后需扩展：草稿 ASN 随旧来源失效；已提交 ASN、ERP 收货及原始分配永久保留，禁止通过失效旧计划释放已提交量。存在历史发货或收货的来源变更先冻结新增协同，记录对账异常；自动接收新版本不等于自动解除冻结。

已发货计划不能通过改期审批重建等量未发货计划。初期保守拒绝其改期；需要修改未发部分时应另行设计余额拆分流程，不能复用整量重建。

## 必须通过的验收

- 100 确认，ASN 30 后净收货仍为 0；ERP 收货 20 后在途 10；再次发货不超过剩余额度。
- 多订单/多工厂多行 ASN 原子提交；一个计划多批；重复行、负量、精度、超量和并发竞争拒绝。
- 收货 30 分配两个 ASN 各 10/20；无 ASN 收货计入余额；部分、全额冲销恢复相应在途但不恢复计划累计发货额度。
- 来源重复/冲突、未知单、先冲销后收货、超收冻结、分页失败及重启从检查点继续。
- 订单改版、缩量、取消、移除行及单位变更不丢在途/收货历史，禁止通过重新确认绕过数量限制。
- 跨供应商/公司/工厂、撤权后幂等重放、过期版本、供应商冻结；失败无审计/业务/幂等副作用。
- 真实 PostgreSQL HTTP、浏览器与部署验收；先备份和隔离回归，再升级现有测试实例；重启和原记录摘要核对。

## 当前实现与运行约定

ASN 无 ERP 发布端点，状态仅 DRAFT/SUBMITTED/CANCELLED/SUPERSEDED。ACKNOWLEDGED/UNKNOWN 属于未来发布协议，不会在当前本地提交中伪造。交货计划按累计有效 ASN 派生 PLANNED/PARTIALLY_SHIPPED/SHIPPED；收货事件保留不可变，收货状态按原单累计冲销派生 POSTED/PARTIALLY_REVERSED/REVERSED。

Mock 收货场景 GR_INITIAL 提供 20 的一收多 ASN 分配（ASN-A 第一行 10、ASN-B 第一行 10），以及两项各 5 的无 ASN 收货；GR_PARTIAL_REVERSE 冲销前者 5，GR_FULL_REVERSE 冲销剩余 15。上述名称是每个连接独立的虚构来源映射，不是核心规则。GR_FAIL_ONCE 在第一页后失败，重试从 sync_job.next_cursor 继续；收货任务不覆盖订单同步游标。隔离事件可在先决条件修复后重新发起同场景，已入账来源键仍去重。

原始异常保存在 receipt_inbox 与 sync_issue，不能在页面人工填数量生成收货。当前冻结采用保守策略：有已提交 ASN 或历史收货的订单改版均冻结新增协同；没有自动解除冻结或生产 ERP 对账功能。已提交 ASN 保留历史，草稿则随来源改版失效。取消不允许任何曾有收货分配的 ASN，即使其收货已全额冲销。
