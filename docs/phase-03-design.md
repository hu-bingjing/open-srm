# Phase 03 实现设计

追加 V4，不改写 V1–V3。订单只由 ERP 读取端口导入，不提供人工创建/修改订单接口。先用 Mock，保持真实 ERP 写入关闭。

## 模型与权限

一条 Mock 连接映射一个公司、采购组织、供应商及有序工厂列表（PLANT-1 等虚构外部键），使用已存在的 Phase 02 主数据，不覆盖它们。创建连接需要 ADMIN 的 sync.manage 动作、公司级 sync.manage 范围及该公司供应商管理范围，页面明确选择映射。创建者为连接负责人；查看/运行/重试还需该负责人身份及当前有效公司级同步范围，其他管理员不自动获得连接权限。首期不提供转移连接负责人，后续独立扩展连接授权。

order.read 动作与完整组织授权元组同时满足。ADMIN/BUYER/AUDITOR/SUPPLIER 均可有读取动作，但均无隐含订单范围。供应商还必须匹配绑定供应商及有效供应商公司关系。列表 total、头可见性、行、计划行及历史均在 SQL 中过滤；历史必须同时满足当前订单可见及历史行授权。响应不含隐藏行数量、汇总或完整快照。

订单来源键为 connection/sourceSystem/sourceClient/externalKey，连接身份不可修改；来源版本保留不透明 sourceRevision，另由适配器提供严格递增 sourceSequence，核心不解析 SAP 版本或 ETag。订单公司、采购组织和供应商不可通过新版本迁移到其他主体；这种事件隔离并冻结一致性。行与计划行采用不可变版本记录，移除的行仍保留在旧版本。

同版本同内容跳过；同版本异内容隔离并冻结；未知旧序列隔离；取消为终态，新的 ACTIVE 不自动重开；CLOSED 可由较新 ERP 版本重新打开。新版本只更新当前指针，不删除历史。数量为 numeric(19,6) 和 API 十进制字符串。Phase 04/05 尚不存在协同记录，本阶段不伪称已验证确认/ASN/收货的跨模块失效；后续须接入同事务版本变更守卫。

## 持久同步

七个 Java 端口放在 integration.port，核心不依赖 adapters.mock。Mock 提供固定快照和不透明分页游标；场景为初始、多版本、重复、乱序、同版本冲突、关闭、取消、取消后重开、移除行、一次故障和持续故障。物料通过独立 MaterialProvider 导入，组织/供应商端口提供虚构读取数据，收货端口本阶段返回空页；发布端口明确 UNSUPPORTED，无真实网络写入。

任务由页面/API 排队，后台每次提交一页；订单、版本、收件去重、异常、审计和任务检查点同事务。一个连接只允许一个活动任务。失败重试沿用任务快照与游标，最多五次人工重试；每次执行重新检查创建者账号、角色、公司范围及连接有效性。任务/异常页面仅返回安全错误码与计数，不返回原始负载或凭据。

Mock 为本地确定性读，当前在既有实例写锁下处理一页，保证多执行器不重复提交；真实 ERP 网络读取与退避调度属于 Phase 06，不能直接把网络调用放进此事务。进程中断时未提交页回滚，已提交游标保留，启动后继续 RUNNING/PENDING 任务。不提供清库、清游标或修改历史接口。

## 验收

保留 Phase 01/02 全量回归。真实 PostgreSQL/HTTP 验证导入、多行多计划、版本不变/重复、乱序、冲突、取消、历史、移除行、分页检查点和失败重试、公司/工厂/采购组织/供应商隔离、计数及历史过滤、撤权和幂等重放、并发同连接任务。浏览器实际创建连接、启动同步、查看订单及版本/异常，部署后重启并核对业务表摘要。升级前备份原库、配置及旧镜像；原账号与主数据保持不变。
