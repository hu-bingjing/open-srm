- Java 21 / Spring Boot 4.1.2 / Maven Wrapper 后端；Vue 3/TypeScript/Vite/Element Plus 前端与锁文件。

- ADMIN/AUDITOR/USER 动作权限；用户创建/状态/角色管理、个人资料、身份审计。
- If-Match、主体/操作/键隔离的幂等响应与 HMAC 请求摘要，业务+审计+幂等结果同事务，最后管理员保护。
- Docker Compose、摘要固定的基础镜像、非 root API/Nginx、内网数据库、自签 HTTPS 测试配置。
- Java 单元测试、真实 PostgreSQL HTTP 验收与 Testcontainers、Playwright 页面测试、源文件扫描及依赖安全流程。

## 验收覆盖

- 初始未认证 401、缺少 CSRF 403、错误初始化令牌拒绝、初始化仅生效一次、BCrypt 存储、登录会话 ID 轮换、HttpOnly/SameSite 与 HTTPS Secure Cookie。
- 用户创建同键重放无重复记录/审计、同键异内容 409、If-Match 冲突 412、无权限 403、未知接口 404、参数错误 400、失败无业务/审计副作用。
- 禁用/启用、角色变更撤销已有会话、普通用户不可管理用户或读取审计、管理员不默认拥有审计权限、保留最后一位有效管理员。
- 并发幂等写入和 16 路并发账号读取；账号读取不在外层结果集持有连接时嵌套获取第二连接。
- 真页面初始化、登录、不同名称写入后刷新读取、用户新建/禁用/启用、普通用户导航与 API 拒绝、注销后 401；浏览器不使用 localStorage 保存会话。
- API 与数据库分别重启后的 JDBC 会话及账号数据保留；这不是备份恢复或跨版本会话兼容验收。

## 环境和过程

用户授权的专用测试主机：Ubuntu 24.04、8 核、约 16 GB 内存、约 67 GB 初始可用磁盘。已安装 Docker Engine 29.9.3 / Compose 5.7.0。
Docker Hub 直连超时，准备阶段尝试过仅回环的临时 SSH 通道。最终应用基础镜像使用发布者官方 ECR 渠道并核对原固定摘要；Ryuk 从官方仓库逐层校验后导入。临时通道已关闭，应用运行不依赖本机代理。
自动审批拒绝了持久修改 Docker 服务代理的方案，该方案未执行；既有 Docker 服务配置未改变。审批也拒绝导出初始化令牌和页面截图，二者均未复制到本机；改为服务器内浏览器验收，凭据和截图留在原部署机。
首轮真实数据库验收发现 PER_CLASS 模式下 Spring 读取映射端口早于容器启动，已在动态配置阶段显式启动，并完整复验通过；未跳过数据库测试。初次依赖审计发现 3.5.x 管理的漏洞依赖，按用户确认升级 4.1.2 后复扫无告警。
