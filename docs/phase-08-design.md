# Phase 08 回归、安全与恢复设计

范围为专用测试实例的发布验证，不授权生产部署、ERP 写入或仓库公开。SAP 真实业务对账独立待补验。升级保留现有 PostgreSQL 卷、账号、业务记录和既有恢复材料；数据库迁移维持 V8。

## 回归与部署门槛

Python 规格/维护工具、Java 单元、真实 PostgreSQL HTTP、Vue 构建与 Playwright 分层执行。HTTP 负向覆盖认证、角色与组织范围、版本、事务审计、并发、幂等和跨域；浏览器验证真实页面和跨站请求。独立 Mock 环境运行完整用例，既有实例只执行使用独立虚构数据的专项用例。SAP 缺数据时明确跳过，不能冒充业务验收。

工作流只读权限，Actions 固定完整 SHA，开发 Python 依赖全量锁定。发布扫描采用明确路径白名单；不上传私有数据、测试日志、截图、恢复包或任何 Actions 附件。未授权建立远端，因此本机同等步骤结果与云端 CI 结果分别记录。

## 安全和依赖

不安全 HTTP 方法除现有 CSRF 外，拒绝跨站 Fetch Metadata；存在 Origin 时必须与部署协议及 HTTP Host/端口完全匹配，拒绝不透明或异常 Origin。TLS 在代理终止，协议取受控的 Secure Cookie 部署配置（HTTPS 必须开启），不信任客户端 Forwarded/X-Forwarded-Proto。保留无 Origin 的认证脚本入口及 CSRF 要求。Nginx 保留原始 Host 端口，TLS 增加 HSTS，隐藏内部管理和私有路径。

OSV、npm、pip 检查应用及开发依赖；Trivy 对实际三个运行镜像扫描漏洞、秘密和许可证声明。高危/严重或秘密发现阻断升级，不压制告警。PostgreSQL 仍为固定摘要的 17.11，派生镜像以固定 Alpine su-exec 替换旧 Go 辅助工具；新卷初始化、原卷启动和恢复均需验证。Web 基础镜像更新并固定摘要。

许可证工具生成可追踪声明清单，识别需审核的条款；它不替代分发适用性判断。项目许可证保持未选择，公开及法律审核为独立门槛。

## 恢复一致性和隔离

维护工具只接受本机测试源站、写入关闭及无待处理任务的部署。API 短暂停止后导出 pg_dump 并计算全部公共表数量与内容摘要，finally 恢复并等待就绪。数据库、源码、三个精确运行镜像及加密的指定配置构成备份；不包含 SAP 配置或 CA 私钥。随机恢复密钥在 private 中另存，不能和备份包一起分发。

恢复先验 SHA256，再解密到全新项目目录，使用新 Compose 项目及新数据卷，禁止覆盖原库。镜像只从本地导出包加载，禁止拉取；API 网络仅内部可达，使用 Mock 且无 SAP 配置。Web 单独入口仅绑定回环。API 启动前逐表比较全部摘要，随后验证会话、初始化状态、统计及既有同步幂等结果。记录停顿、导出、导入与总恢复时间。SHA256 防意外损坏，不证明备份来源真实性；保管目录、密钥及离线副本仍须受控。

性能测试仅在验证通过的恢复副本，以固定并发和请求数读取四个查询端点；报告数据规模、错误、分位延迟及吞吐，不将小规模读测试解释为生产容量。
