# Phase 07：工作台、站内通知和统计

## 验收口径

新增真实后台读模型、Vue 页面和 V8 追加迁移。保留所有既有业务行和 outbox_event；新 notification_delivery 保存投递状态，notification 保存接收者自己的站内消息。不发送邮件、外部消息或 ERP 请求。

工作台为已登录用户提供待确认计划行、本人不能自批的待审批申请、逾期未发完计划、冻结订单、同步失败及可见未读数量；待办只纳入当前有效订单/版本，操作仍走原命令接口。用户没有业务动作权限时相应待办为空。逾期按公司时区当日判断。

统计按公司、工厂、单位分组，不汇总不同单位。订购/生效确认/待审批确认只计当前订单版本；订购量是最新来源快照原始量，包含关闭/取消快照，不表示未结采购量；有效 ASN、ERP 净收货和 ASN 在途保留历史版本。净收货为 POSTED 减 REVERSAL；在途按每条有效 ASN 行数量减其净收货分配后取不小于零。未分配收货不减少其他 ASN 的在途。统计 SQL 在聚合前应用当前完整公司/工厂/采购组织元组和供应商绑定。可按公司、工厂、采购组织、供应商进一步缩小范围。

## 通知与失败恢复

复用事务内 outbox；独立投递表唯一来源类型/来源标识/来源版本，消息唯一投递/接收人/站内渠道。同步失败在原同步事务落入新投递表，订单冻结在现有冻结事务记录通用冲突通知。原业务事件不修改。投递前校验来源版本和状态，已过期事件标记 SUPERSEDED，不发送失效待办。消息仅保存类型和业务引用，不复制原因、凭据、响应或数量。

接收者必须当前有效且具备相应业务读取权限；行事件还要求该行工厂范围。同步失败只发给拥有该连接且仍有同步权限的操作人。列表、未读计数、详情、已读及幂等重放均重新检查归属和实时数据范围；撤权/解绑/组织停用后不可见。

后台按独立事务投递，成功消息和状态同事务，失败回滚全部消息后记录安全错误码及有限退避，最多自动尝试 5 次。管理员只能在自己有范围权限的事件上查看投递和按版本手动重试，重试使用幂等和事务审计；不提供任意收件人或负载输入。新增投递日志为系统处理账本，已读和人工重试走现有命令审计。重放不会重复生成消息，后续新授权用户不追补已经完成的历史投递。

## 必需验证

PostgreSQL HTTP：授权与跨公司/工厂/采购组织/供应商负向、已读归属/版本/幂等、撤权后列表计数和重放、outbox 重放、失效事件、投递事务回滚和失败重试、统计独立 SQL 对账。浏览器：真实工作台/统计/通知刷新与已读、投递监控；完整回归仅隔离实例。Ubuntu：升级前备份及原行指纹、隔离验收后保留数据卷升级、定向 HTTPS、API/数据库重启与通知/业务持久化、原记录核对。SAP 真实业务数量对账继续待补验，ERP 写入保持 false。
