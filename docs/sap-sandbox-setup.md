# SAP 开发/测试环境只读接入准备

适用于 Phase 06。真实环境地址、系统标识、组织代码、账号及凭据只保存在部署主机 private/；本文不记录这些值。开发/测试共用系统也需要限制数据范围和访问窗口，避免影响其他测试。

## 1. 先收集现有系统信息，不修改配置

用 SAP GUI 登录开发/测试客户端，打开“系统 → 状态”，记录当前 Client（三位）、系统标识、产品版本及已安装软件组件版本；在产品版本详情中核对 S/4HANA 发布版本、FPS/SPS。不同 SAP GUI 版本按钮文字略有差异。

记录当前是否有可用 Fiori/网页入口及其完整 URL。应用服务器地址不一定是 SAP Gateway 或 Web Dispatcher 的入口，不根据地址猜端口。若没有网页入口，请 SAP Basis 管理员核对 ICM 的 HTTPS 监听与 Gateway 部署方式。

不要提供个人口令、SAP_ALL 账号、私钥或未经脱敏的业务屏幕。可将必要技术信息通过私有配置交付，不进入仓库。

## 2. 由 Basis 管理员核实 HTTPS 和 Gateway

确认是嵌入式还是独立 Gateway；提供 SRM 测试服务器实际应访问的 HTTPS 服务根地址，网络仅放行所需源/目的和端口。证书 SAN 应匹配访问名称；将内部 CA 信任链配置进客户端信任库，不关闭证书校验，不通过明文 HTTP 传口令。

## 3. 核实并启用只读业务服务

候选 OData V2 服务为 API_PURCHASEORDER_PROCESS_SRV（采购订单）及 API_MATERIAL_DOCUMENT_SRV（物料凭证）。候选名称不保证目标 1909 的当前补丁与组件已提供；需在该系统核实，不能套用最新公有云文档认定支持。

Basis 在 /IWFND/MAINT_SERVICE 检查已有服务及系统别名；需要新增时按系统提供的服务版本注册，并核实相关 ICF 节点。若候选服务不存在，先检查组件/补丁和适用接口，不任意启用所有服务，不自行开发或导入未知增强。

启用后，由 Basis 获取两项服务的 $metadata 及少量脱敏样例，核对订单头、行、计划行、物料/单位、变更时间/ETag、删除/关闭标识，以及收货凭证年度/单号/行、订单引用、数量、单位、移动类型和原收货冲销引用。接口未给出唯一计划行时不能猜测分配。

## 4. 建立专用技术账号及最小只读角色

由安全管理员创建独立集成账号，账户类型、认证方式和口令策略按组织标准确定。优先采用系统已经支持的 HTTPS 认证方案；账号或服务授权不能以 SAP_ALL/SAP_NEW 或完整仓库业务角色替代。

PFCG 角色只加入批准的 Gateway 服务执行授权及业务读取权限。采购订单常见检查对象 M_BEST_BSA、M_BEST_EKG、M_BEST_EKO、M_BEST_WRK，活动限定 03（显示），并限制实际单据类型、采购组、采购组织及工厂。它们是核对起点，不是适用于所有 OData 实现的完整角色模板；实际对象、Gateway 前后端角色和物料凭证显示权限由目标服务的 SU24 建议及授权跟踪确定。

公司、工厂、采购组织、供应商和测试时间/单据范围必须明确。组织过滤既在 SAP 权限层落实，也在适配器请求及本地映射中落实；不能只依赖前端筛选。不要授予创建、更改、删除、取消或物料过账权限；OData 模式不额外授予广泛 RFC、表读取或通用函数执行权限。

## 5. 只读连通与授权验证

由管理员先验证：GET $metadata、GET 单条批准范围的订单及物料凭证。遇到 401 核实认证，403 用授权跟踪定位最小缺口，不通过放大角色绕过。不要为验证“禁止写入”而在真实系统尝试 POST/PATCH/DELETE；写入拒绝由角色审查、服务/网关策略和本地模拟服务测试验证。

完成后提供：HTTPS 根地址、Client、服务版本/路径、认证类型、CA 信任链、批准组织范围、经脱敏的 metadata 和样例。凭据保存在测试服务器的受限私有配置/secret 中，不发送到公开代码、日志或报告。

## 6. OpenSRM 启用门槛

开发合同测试与真实 SAP 联调分别验收。仅在用户确认非生产目标、只读范围及窗口后启用私有连接；默认仍为 Mock，ERP 写入始终关闭。第一次只读试拉选择少量明确单据，并核对 SAP 原数量、单位、计划行和收货/冲销净额；再验证分页、来源变更和故障恢复，不能直接全量扫描。
