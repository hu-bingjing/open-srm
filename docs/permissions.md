# 角色与数据权限矩阵

角色只提供动作能力，数据范围另外授予。超级管理员也不自动获得业务数据。

## Phase 02 已实现权限

| 角色 | 动作能力 | 数据范围 |
| --- | --- | --- |
| ADMIN | 用户/角色、组织目录、组织授权及供应商绑定管理；供应商读写 | 目录为部署级管理；供应商必须另授公司级范围 |
| BUYER | 组织目录读取、供应商读取/维护 | 显式有效授权元组 |
| SUPPLIER | 组织目录及供应商只读，与其他角色互斥 | 单个绑定供应商、有效公司关系、有效授权交集 |
| AUDITOR | 身份审计、组织目录、业务审计 | 身份事件延续 Phase 01；业务事件另需公司级 audit.read |
| USER | 个人账号 | 不因拥有范围记录而自动获得业务动作 |

供应商档案是公司级资源，工厂/采购组织限制授权只提供对应目录范围，不能读取整个公司的供应商或业务审计。共享供应商主档名称/冻结状态修改要求全部历史关联公司管理范围；关系停用保留历史，内部授权用户仍可维护。公司、工厂、采购组织停用及关系撤销立即令相关范围失效；重新绑定供应商使旧会话失效。

## 范围模型

Phase 04 供应商确认要求 SUPPLIER 动作、正确绑定、order.read 范围及 confirmation.submit 范围；采购审批要求 BUYER 动作、order.read 范围及 delivery.approve 范围。动作范围必须同一元组覆盖目标公司/工厂/采购组织。ADMIN 不自动获得这些业务动作或范围。
仅申请人可撤回本人待批申请；服务层禁止申请人自批，即使底层角色动作误配置也不放行。有效承诺改期可由同供应商授权操作员提出，但仍需独立采购审批。

Phase 03 增加 order.read 范围，必须同一元组覆盖订单公司、行工厂与采购组织；历史同时要求当前订单和历史行可见，不返回完整原始快照。ADMIN/BUYER/AUDITOR/SUPPLIER 有订单读取动作，仍需显式范围；供应商绑定与有效公司关系继续同时校验。
ADMIN 的 sync.read/sync.manage 动作还需公司级 sync.manage 范围及连接负责人身份。创建连接还需该公司供应商管理范围与有效映射，其他管理员不自动看到连接、任务或隔离事件。仅提供角色与范围，不引入隐含订单授权。

`organization_grant(subject, permission, company_id, plant_id?, purchasing_org_id?)` 是一个完整授权元组。
判断时必须找到**同一个元组**同时覆盖对象的公司、工厂、采购组织；多条授权取并集，但不能把一个元组的公司和另一个的工厂拼接。
空工厂/采购组织表示该公司内对应维度全部；公司不能空。采购组织与公司关联必须有效，工厂必须属于该公司。
供应商主体还必须同时满足 `user_supplier.supplier_id = order.supplier_id`、供应商公司关系有效、所需动作已授予、组织元组匹配。首期一个供应商用户仅绑定一个供应商，切换供应商不靠客户端参数。
组织越界、供应商越界、对象不存在对外统一 404；未认证 401；已认证但无动作能力 403。成功写入保留同事务审计；本阶段不把所有业务拒绝另写审计表。

列表、统计、导出、详情、关联对象、写操作、批量操作、异步任务和缓存均应用相同过滤。不能先分页再在内存滤权限；聚合数量也不能泄露其他组织。
订单头可能包含多工厂行：只要至少一个行可见才返回头信息，响应的行、计划行与数量汇总只能包含当前授权范围；无权查看的行及其数量不返回。涉及多个行的写命令必须逐行全部授权，否则整体拒绝。ASN 头同理，不能用头级可见性代替逐行校验。
写入不得信任请求提供的 company/supplier：以数据库订单或经校验主数据推导。通知与审计附件也需范围检查。

## 必测负向场景

1. Supplier A 无法读取 Supplier B 的详情，即使猜中 UUID；ASN 不能引用他人的计划行。
2. Company A 授权不能读取 Company B；有两个不相交授权仍不能拼接越界访问。
3. 供应商服务两家公司不代表每个供应商用户都有两家公司的权限。
4. 管理员未经业务范围授权无订单可读；集成运维不能看到原始凭据/业务负载。
5. 申请者兼任审批人仍禁止自批；已撤销授权者不能通过幂等重放取回旧响应。
6. 批量请求混入一个越权对象则整批拒绝，不出现部分写入或数量泄露。
7. 禁用用户/冻结供应商后阻止新写入；历史保留并按权限只读。

Phase 00 可执行规格覆盖核心范围匹配与自批规则；Phase 02 已增加真实 PostgreSQL/HTTP 目录、供应商及撤权测试。订单行权限、审批和异步上下文仍待对应业务阶段实测。

## Phase 05

SUPPLIER 增加 asn.manage 动作能力，仍必须显式授予同名组织范围并同时具有 order.read 和有效供应商绑定。系统管理员没有默认 ASN 写入能力。ASN 头、计数和详情要求全部行授权；无绑定及部分工厂授权不能泄露其他行。收货读取使用订单及历史行权限；同步使用现有连接所有者及公司完整 sync.manage 范围。幂等缓存重放同样先检查当前权限/绑定、来源版本和冻结。

Phase 07：工作台为已认证用户提供当前可见读模型；统计必须 order.read 并复用完整元组/绑定过滤。通知投递和读取均检查当前业务读取权限，行事件额外校验对应工厂；同步失败只归属连接所有者且需同步组织授权。已读仅本人，详情/总数/未读/幂等重放同样过滤。投递监控与人工重试要求 user.manage、非供应商身份和对应业务范围，不赋予管理员默认全组织读取权。
